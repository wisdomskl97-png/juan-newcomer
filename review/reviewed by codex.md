# Reviewed by Codex

## 리뷰 대상

- 최종 기획안: `plan/juan_newcomer_app_plan_final_codex.md`
- 프로토타입: `design/prototype/주안 새가족등록.dc.html`

요청에 따라 프로토타입 파일은 수정하지 않고 읽기 전용으로만 확인했다.

## 총평

Claude 디자인 프로토타입은 최종 기획안의 핵심 방향을 꽤 잘 반영하고 있다. 특히 모바일 우선 화면, 첫 질문을 통한 일반목장/대학목장 분기, 대학목장 별도 입력 흐름, 당일 요약 화면, 복사/공유 기능, 팀원용 PIN 화면까지 들어가 있어 단순 폼보다 훨씬 운영 흐름에 가깝다.

다만 실제 MVP 개발로 넘어가기 전에 반드시 보완해야 할 부분이 있다. 가장 중요한 것은 **개인정보 동의**, **등록일 자동 저장 기준**, **대학목장 정보 전달 UX**, **실제 Google Sheets/DailySummary 저장 구조**다.

## 잘 반영된 부분

### 1. 첫 화면 분기

기획안의 핵심 요구였던 “학생비자 또는 시드니 대학 재학/입학 예정 여부” 질문이 첫 흐름에 잘 들어가 있다.

- `chooseYes`는 대학목장 폼으로 이동한다.
- `chooseNo`는 일반목장 폼으로 이동한다.

이 구조는 대학목장 대상자가 일반 등록 폼으로 바로 들어가는 실수를 줄이는 방향이다.

### 2. 일반목장/대학목장 폼 분리

프로토타입은 일반목장 등록 폼과 대학목장 인계 폼을 별도 화면으로 구성했다. 이는 기획안의 “같은 폼에서 필터링하지 않고 첫 질문 이후 다른 코드 경로로 분리한다”는 원칙과 잘 맞는다.

### 3. 대학목장 정보 입력 및 전달 메시지

대학목장 폼에서 이름, 연락처, 카카오톡 ID, 생년월일, 비자, 전공, 인도자, 세례 여부, 이전 출석교회, 이전 봉사부서 등을 받을 수 있게 되어 있다.

또한 대학목장 전달 메시지를 생성하고, 복사/공유할 수 있는 화면도 있다. 이 방향은 기획안의 “대학목장 정보는 일반 DB에 저장하지 않고 공유용 메시지로 전달”한다는 MVP 방향과 잘 맞는다.

### 4. 당일 요약 화면

팀원용 등록 요약 화면이 구현되어 있고, 일반목장/대학목장 카운트와 필터링이 가능하다.

요약 리스트에는 이름, 태어난 해, 목장 구분이 표시된다. 이는 기획안의 “당일 요약에는 이름과 태어난 해만 표시” 요구와 잘 맞는다.

### 5. 복사/공유 기능

`navigator.share` 기반 공유와 클립보드 복사 fallback이 들어가 있다. 모바일에서 카카오톡, 메시지, 이메일 등으로 공유할 수 있는 방향이므로 MVP에 적합하다.

### 6. 한 명 더 등록하기

일반목장/대학목장 완료 화면 모두 “한 명 더 등록하기” 버튼이 있다. 가족 또는 한 기기로 여러 명을 등록하는 현장 상황을 잘 반영했다.

### 7. 팀원용 요약 접근 보호

팀원용 요약 화면에 4자리 PIN을 둔 것은 좋은 방향이다. MVP 단계에서는 완전한 로그인보다 가볍고, 새가족이 우연히 요약 화면에 들어가는 것을 어느 정도 막을 수 있다.

## 보완이 필요한 부분

### 1. 개인정보 동의 UI와 검증이 빠져 있음

기획안에서는 개인정보 수집 및 이용 동의를 MVP 필수 기능으로 정의했다. 프로토타입 상태에는 `consent` 값과 핸들러가 있지만, 실제 화면에서 동의 체크박스나 동의 문구가 보이지 않고, 제출 검증에도 포함되어 있지 않다.

현재 상태:

- `form.consent` 상태는 있음
- `h.consent` 핸들러도 있음
- 그러나 일반/대학 폼에 동의 체크 UI가 없음
- `validateGeneral`, `validateUniv`에서 동의 여부를 검사하지 않음

개발 전 반드시 추가해야 한다.

추천:

- 일반목장 폼 제출 전 개인정보 동의 체크 필수
- 대학목장 폼도 “대학팀 인계를 위한 개인정보 공유 동의” 체크 필수
- 미동의 시 제출 불가

### 2. 등록일 자동 저장이 명확히 구현되어 있지 않음

기획안에서는 `submitted_at`과 별도로 `registration_date`를 저장하도록 정리했다. 프로토타입에서는 제출 시 `today` 배열에 이름, 출생연도, 목장 구분, 상세 info만 추가된다.

현재 문제:

- `registration_date` 필드가 없음
- `submitted_at` 필드가 없음
- 요약 화면 날짜는 실제 입력일이 아니라 `serviceSunday()`로 계산한 날짜를 사용함

특히 `serviceSunday()`는 오늘 날짜가 아니라 “다가오는 주일”을 계산한다. 사용자가 토요일에 테스트하면 다음날 주일로 표시될 수 있다. 기획안의 기준은 “앱에 정보를 넣었던 날”이므로 실제 제출 날짜를 저장해야 한다.

추천:

- 제출 시 `registration_date = YYYY-MM-DD`를 시드니 현지 날짜 기준으로 생성
- `submitted_at = ISO datetime` 또는 Apps Script 서버 시간으로 저장
- 요약 날짜도 `registration_date` 기준으로 표시

### 3. 대학목장 제출 직후 공유 UX가 약함

대학목장 제출 로직은 `shareMsg`를 생성한다. 하지만 대학목장 완료 화면에는 바로 복사/공유 버튼이 보이지 않는다. 현재는 팀원용 요약 화면에 들어가서 “대학목장 전달 메시지 만들기”를 눌러야 전달 메시지를 볼 수 있다.

기획안은 대학목장 등록 후 카카오톡/이메일/복사로 대학팀에게 바로 보낼 수 있는 흐름을 원했다.

추천:

- 대학목장 완료 화면에 바로 아래 버튼을 추가
  - 대학팀 전달 메시지 보기
  - 복사하기
  - 공유하기
- 팀원이 대신 입력한 상황에서는 제출 직후 바로 공유할 수 있어야 한다.

### 4. 실제 저장 구조는 아직 목업 상태

프로토타입은 디자인 목업이므로 실제 Google Sheets, Apps Script, `DailySummary` 연동은 없다. 이것 자체는 문제라기보다 다음 개발 단계에서 꼭 구현해야 할 항목이다.

기획안 기준으로 실제 개발 시 필요한 저장 구조:

- 일반목장 상세 정보: `Newcomers`
- 당일 요약: `DailySummary`
- 대학목장 상세 정보: 일반 `Newcomers`에는 저장하지 않음
- 대학목장 공유 메시지: 복사/공유 또는 2차에서 이메일 발송

현재 프로토타입의 `today` 배열은 일반목장과 대학목장 상세 정보를 모두 브라우저 상태에 담는다. 프로토타입에서는 괜찮지만, 실제 구현에서는 대학목장 상세 정보가 일반 DB 저장 요청으로 섞이지 않게 API endpoint 또는 request type을 분리해야 한다.

### 5. 요약 복사 텍스트는 “오늘” 기준만 사용함

프로토타입에는 지난 기록 보기 기능이 있다. 하지만 `summaryText()`는 현재 선택된 archive가 아니라 `this.state.today`만 기준으로 문자열을 만든다.

기획안의 MVP는 당일 요약이므로 큰 문제는 아니지만, 지난 기록 기능을 유지할 경우에는 선택된 날짜의 active list를 기준으로 복사 텍스트를 만들어야 한다.

추천:

- MVP에서는 지난 기록 기능을 숨기거나
- `summaryText()`가 `activeList()` 기준으로 작동하도록 개발 단계에서 수정

### 6. 요약 화면의 샘플 데이터 기본값

프로토타입은 `seedSampleList` 기본값이 true이고, 기본 today 목록에 샘플 새가족이 들어가 있다.

프로토타입 시연에는 좋지만 실제 앱에서는 위험하다.

추천:

- 실제 배포 버전에서는 샘플 데이터 제거
- 개발/데모 모드에서만 샘플 데이터 표시

### 7. 팀원 PIN은 프로토타입 수준

팀원용 요약 PIN 기본값이 `1234`다. 프로토타입에서는 충분하지만, 실제 배포에서는 최소한 환경 설정으로 바꿀 수 있어야 한다.

추천:

- MVP: 설정값으로 PIN 관리
- 이후: 관리자 로그인 또는 비공개 관리 URL 검토

## 우선순위별 수정 제안

### Must Fix Before MVP Development

1. 일반목장/대학목장 폼에 개인정보 동의 체크박스 추가
2. 동의하지 않으면 제출 불가하도록 validation 추가
3. 제출 데이터에 `registration_date`와 `submitted_at` 추가
4. 대학목장 완료 화면에서 바로 복사/공유할 수 있는 버튼 추가
5. 실제 저장 요청에서 일반목장과 대학목장 request type 분리
6. `DailySummary`에는 이름, 태어난 해, 목장 구분, 등록일만 저장하도록 설계

### Should Fix

1. 요약 복사 텍스트를 현재 선택한 날짜 기준으로 생성
2. 샘플 데이터는 데모 모드에서만 표시
3. 팀원 PIN 기본값을 실제 배포 설정에서 변경 가능하게 처리
4. 대학목장 전달 메시지에 포함할 필드 범위를 최종 확정

### Nice to Have

1. 요약 화면에 “오늘 요약 새로고침” 버튼
2. 대학팀 이메일 자동 발송 옵션
3. 오프라인 임시 저장 후 재전송
4. 중복 연락처 감지

## 디자인 의견

전체 디자인은 따뜻하고 교회 새가족 등록이라는 목적에 잘 맞는다. 로고 사용, 한국어/영어 병기, 큰 버튼, 섹션 분리, 완료 화면의 톤이 좋다.

다만 실제 앱으로 만들 때는 입력 폼이 조금 길게 느껴질 수 있다. 특히 대학목장 폼도 상세 항목이 많기 때문에, 현장에서 1-2분 안에 입력시키려면 필수 항목을 더 줄이는 선택지가 필요하다.

추천 필수 항목:

- 이름
- 연락처
- 생년월일 또는 태어난 해
- 개인정보 동의

선택 항목:

- 카카오톡 ID
- 비자
- 전공/직업
- 인도자
- 세례 여부
- 이전 교회/봉사 부서

## 최종 의견

프로토타입은 방향성이 좋고, 최종 기획안의 핵심을 대부분 시각적으로 잘 구현했다. 특히 대학목장 분기와 당일 요약 기능은 운영 상황을 잘 반영했다.

다음 단계에서 가장 조심해야 할 점은 “보기에는 분리되어 있지만 실제 저장에서 섞이는 문제”다. 개발할 때는 일반목장 저장 API, 대학목장 공유/전달 처리, DailySummary 저장을 명확히 분리해야 한다.

MVP 개발로 넘어가기 전에 개인정보 동의와 등록일 저장만 확실히 보완하면, 이 프로토타입은 충분히 좋은 기준안으로 사용할 수 있다.
