## 프롬프트 (아래 내용을 그대로 복사해서 사용)

```
시드니 주안교회 새가족 등록 앱 "주안 새가족등록"의 화면 디자인을 HTML/CSS로 만들어줘.

# 브랜드 아이덴티티
- 로고: 노랑/주황/핑크/보라/파랑이 겹치는 3개의 원(Venn diagram) 모티프 위에 흰색 손글씨체 십자가, "SYDNEY JOOAN CHURCH" 텍스트가 겹쳐진 로고. 원이 겹치는 부분에서 주황(노랑+빨강 계열), 보라(보라+파랑), 갈색(중앙 겹침), 핑크(상단 겹침) 톤이 자연스럽게 생김.
- 로고 파일 경로: image/juanlogo.png (있는 그대로 첫 화면 상단에 배치)
- 톤앤매너: 따뜻하고 환영하는 느낌, 그러나 산만하지 않게. 로고의 다채로운 색은 포인트로만 쓰고, 본문/폼 영역은 화이트/뉴트럴 베이스에 절제된 색상 사용.

# 컬러 팔레트 제안
- Primary: 로고의 보라~파랑 계열 (#5B4B8A ~ #3B6FA5 사이 톤)
- Accent: 로고의 주황~핑크 계열 (버튼 hover, 강조 배지 등에만 소량 사용)
- Background: 오프화이트 (#FAFAF8 계열)
- Text: 짙은 회색/네이비, 검정 대신 부드러운 톤

# 앱 정보
- 앱 이름: 주안 새가족등록
- 사용 맥락: 새가족이 예배 후 QR코드를 스캔해 본인 휴대폰으로 직접 등록. 팀원이 대신 입력하는 경우도 있음.
- 언어: 한국어/영어 병기 (라벨은 "이름 / Name" 형태)
- 디바이스: 모바일 우선 (375px~430px 폭 기준), 큰 터치 영역, 읽기 쉬운 폰트 크기(본문 16px 이상)

# 만들어야 할 화면 (총 6개 + 서브 화면 1개)

## 1. QR 접속 첫 화면
- 상단에 juanlogo.png 로고
- "주안 새가족등록" 타이틀
- 짧은 환영 문구 1~2줄 (한/영 병기)
- "시작하기" 큰 버튼 1개
- 화면에 정보 입력 요소는 없음. 다음 단계로 넘어가는 것이 유일한 목적.

## 2. 목장 분류 질문 화면
- 진행 표시(예: 1/2 스텝 인디케이터) 상단에
- 질문: "현재 학생비자이거나, 시드니에서 대학 재학 또는 입학 예정이신가요?" (영문 병기)
- "예" / "아니오" 두 개의 큰 버튼 (뒤로가기/건너뛰기 없음 — 반드시 선택해야 다음으로 진행)
- 이 화면이 왜 중요한 화면인지: 이후 전혀 다른 흐름(등록 폼 vs 안내 화면)으로 분기됨. 버튼 두 개 모두 명확하고 오해 없이 구분되게 디자인.

## 3. 일반목장 새가족 등록 폼 (목장분류에서 "아니오" 선택 시)
- 섹션을 2~3개로 나눠서 표시 (기본정보 / 교회관련정보 / 생활정보), 한 화면에 다 몰아넣지 않기
- 입력 필드: 이름/Name(필수), 연락처/Contact(필수), 카카오톡ID(선택), 생년월일(선택), 인도자(선택), 비자종류(필수, select: 워킹홀리데이/영주권/시민권/여행/학생/기타), 전공또는직업(선택), 세례여부(선택), 이전출석교회(선택), 이전봉사부서(선택)
- 하단에 개인정보 수집·이용 동의 체크박스(필수) + 동의 문구 요약 + "자세히 보기" 링크
- "제출하기" 버튼 (필수 항목 미입력 시 비활성 또는 인라인 에러 표시)

## 4. 대학목장 안내 및 인계 화면 (목장분류에서 "예" 선택 시)
- 상단에 "대학목장" 배지/라벨로 일반 흐름과 시각적으로 명확히 구분 (예: 다른 accent color 사용)
- 안내 문구: 대학팀이 별도로 연락드린다는 내용
- 대학팀 인계용 정보 입력 폼: 이름, 연락처, 카카오톡ID, 태어난 해, 비자종류, 전공, (선택) 인도자
- 이 정보는 DB에 저장되지 않고 공유 메시지 생성용이라는 점을 화면 어딘가에 작게 명시 (예: "이 정보는 별도 저장되지 않으며, 대학팀 전달용으로만 사용됩니다")
- 제출 시 다음 화면(공유 메시지 생성)으로 이동

## 5. 제출 완료 화면 (일반목장 제출 후 / 대학목장 공유 메시지 생성 후 공통 레이아웃, 내용만 분기)
- 체크마크 또는 환영 아이콘
- 감사 메시지 (한/영)
- "한 명 더 등록하기" 버튼
- (대학목장의 경우) 생성된 공유 메시지 미리보기 박스 + "복사하기" / "공유하기" 버튼

## 6. 당일 요약 화면 (팀원용, 새가족이 보는 화면 아님)
- 오늘 등록된 명단을 리스트로: 이름 + 태어난 해 + 배지(일반목장/대학목장)
- 상단에 총 인원수 요약 ("오늘 총 N명 등록: 일반목장 N명 / 대학목장 N명")
- "복사하기" / "공유하기" 버튼
- 목록 항목 디자인에서 일반목장/대학목장을 색상 배지로 명확히 구분
- 개인정보(연락처 등)는 절대 이 화면에 노출하지 않음 — 이름+태어난해만

# 인터랙션/상태
- 각 화면 전환 시 자연스러운 전환감 (fade/slide 정도, 과하지 않게)
- 폼 검증 에러는 필드 바로 아래 빨간 텍스트로, 색만으로 구분하지 말고 아이콘도 함께
- 버튼은 로딩 상태(제출 중) 표시 필요

# 산출물 형식
- 반응형 HTML/CSS 단일 파일 또는 화면별 섹션으로, 실제 코드로 만들어줘 (목업 이미지가 아니라 브라우저에서 바로 확인 가능한 형태)
- 모바일 뷰포트 기준으로 보여주되, 데스크톱에서도 깨지지 않게
- 다크모드는 고려하지 않아도 됨 (교회 현장 태블릿/폰 사용 기준)
```

## 프롬프트 사용 방법

1. 위 코드블록 전체를 복사한다.
2. Claude와의 새 대화(또는 이 대화)에서 붙여넣고, `image/juanlogo.png` 파일을 함께 첨부하거나 경로를 알려준다.
3. 결과로 나온 HTML/CSS 시안을 보고 다음을 피드백한다.
   - 색상 톤이 로고와 잘 어울리는지
   - 목장 분류 화면의 "예/아니오" 버튼이 충분히 명확한지
   - 대학목장 화면이 일반 화면과 시각적으로 잘 구분되는지
   - 당일 요약 화면에서 개인정보 노출이 없는지
4. 피드백 반영 후 확정되면, 이 디자인을 기준으로 `plan/juan_newcomer_app_plan_final_codex.md`의 "13. MVP 개발 범위"에 따라 실제 `index.html` / `styles.css` / `script.js` 개발에 들어간다.
