# 주안 새가족 등록앱 기획안

## 1. 프로젝트 개요

### 목적

시드니 주안교회에 매주 방문하거나 등록하는 새가족들이 QR 코드를 통해 직접 정보를 입력하고, 교회 새가족팀이 해당 정보를 효율적으로 관리할 수 있는 등록 및 관리 앱을 만든다.

현재는 새가족이 교회에 방문했을 때 종이 등록지를 작성하고, 팀원이 이후 Google Form에 정보를 입력해 Google Sheets에 저장하는 방식이다. 이 과정은 팀원의 수고가 크고, 대학목장 대상자가 실수로 일반 새가족 데이터베이스에 저장되는 문제가 발생할 수 있다.

이 앱은 등록 과정을 간소화하고, 일반목장과 대학목장 대상자를 처음부터 정확히 분류하는 것을 핵심 목표로 한다.

## 3. 현재 등록 방식

### 현재 프로세스

1. 새가족이 교회에 방문한다.
2. 팀원이 종이 등록지를 전달한다.
3. 새가족이 종이에 정보를 작성한다.
4. 팀원이 해당 정보를 Google Form에 입력한다.
5. Google Form 응답이 Google Sheets에 저장된다.

### 현재 받고 있는 정보

- 이름 / Name
- 연락처 / Contact
- 인도자 / Introducer

  - 시민권
  - 여행
  - 학생
  - 기타

- 이전 봉사 부서 / Activities involved in previous church
- 카카오톡 아이디 / KakaoTalk ID

## 4. 중요한 운영 조건

시드니 주안교회는 새가족을 크게 두 목장으로 나누어 관리한다.

- 일반목장
- 대학목장

현재 운영 방식에서는 새가족을 만났을 때 먼저 말로 아래 내용을 확인한다.

- 학생비자인지
- 시드니에서 대학 재학 중인지
- 시드니에서 대학 입학 예정인지

위 조건에 해당하면 대학목장 대상자로 분류하고, 기존 일반 새가족 등록 흐름이 아니라 대학팀에 정보를 전달한다. 이 정보는 일반 새가족 데이터베이스에 저장되지 않아야 한다.

따라서 앱에서는 등록 초반에 일반목장과 대학목장 대상자를 분류하는 질문이 반드시 필요하다.

## 5. 추천 등록 흐름

### 전체 흐름

1. 새가족이 QR 코드를 스캔한다.
2. 앱 첫 화면에 접속한다.
3. 목장 분류 질문에 답한다.
4. 답변에 따라 일반목장 또는 대학목장 흐름으로 이동한다.

### 첫 질문 예시

> 현재 학생비자이거나, 시드니에서 대학 재학 또는 입학 예정이신가요?

### 일반목장 대상자 흐름

1. 새가족 등록 폼으로 이동한다.
2. 필요한 정보를 입력한다.
3. 개인정보 수집 및 이용에 동의한다.
4. 제출한다.
5. 정보가 새가족 데이터베이스에 저장된다.
6. 제출 완료 화면을 보여준다.

### 대학목장 대상자 흐름

1. 대학목장 안내 화면으로 이동한다.
2. 대학팀 담당자 연락처 또는 별도 대학목장 등록 링크를 제공한다.
3. 일반 새가족 데이터베이스에는 저장하지 않는다.

이 방식은 대학목장 대상자가 실수로 일반 새가족 데이터베이스에 저장되는 문제를 줄인다.

## 7. 데이터베이스 추천

### 현재 선택지

- Google Sheets
- Notion

### 1차 추천: Google Sheets 유지

초기 MVP 단계에서는 Google Sheets를 유지하는 것을 추천한다.

이유:

- 현재 Google Form과 Google Sheets 기반 운영 경험이 있다.
- 팀원들이 이미 익숙할 가능성이 높다.
- HTML 앱에서 Google Apps Script를 통해 저장하기 비교적 쉽다.
- 빠르게 MVP를 만들고 실제 주일 현장에서 테스트하기 좋다.
- 별도 관리자 페이지 없이도 Google Sheets 자체를 관리 화면처럼 사용할 수 있다.

### Notion이 적합한 경우

Notion은 아래와 같은 관리 방식이 필요할 때 적합하다.

- 새가족 한 명 한 명을 카드처럼 관리하고 싶을 때
- 담당자, 연락 상태, 메모, 후속 조치를 보기 좋게 관리하고 싶을 때
- 팀원들이 Notion 사용에 익숙할 때
- 새가족 관리를 CRM처럼 운영하고 싶을 때

### 추천 단계

1. 1차 MVP는 Google Sheets 저장으로 시작한다.
2. 실제 운영 흐름을 테스트한다.
3. 필요한 관리 항목과 담당자 흐름이 명확해지면 Notion 연동을 검토한다.
4. 최종적으로 Notion을 새가족 관리 CRM처럼 사용할 수 있다.

## 9. 개발 단계 플랜

### 1단계: 기획 정리

결정할 내용:

- 앱 이름
- 일반목장과 대학목장 분류 기준
- 필수 입력 항목
- 대학목장 대상자의 데이터 저장 여부
- Google Sheets로 시작할지 Notion으로 바로 갈지
- MVP에 관리자 화면이 필요한지 여부

산출물:

- 등록 플로우
- 데이터 항목 정의
- 화면 목록
- 데이터베이스 구조 초안

### 2단계: 디자인

필요한 화면:

1. QR 접속 첫 화면
2. 목장 분류 질문 화면
3. 일반목장 새가족 등록 폼
4. 대학목장 안내 화면
5. 제출 완료 화면
6. 관리자 목록 화면

디자인 방향:

- 모바일 우선
- 교회 분위기에 맞는 따뜻하고 차분한 디자인
- 한 화면에 너무 많은 입력 항목을 넣지 않기
- 한국어와 영어 병기
- 큰 버튼과 읽기 쉬운 폰트 사용
- 새가족이 부담 없이 작성할 수 있는 문장 사용

### 3단계: MVP 개발

추천 기술 구성:

- Frontend: HTML, CSS, JavaScript
- Database: Google Sheets
- Backend or API: Google Apps Script
- Deployment: Netlify, Vercel, GitHub Pages 중 선택

MVP 기능:

- QR로 접속 가능한 등록 페이지
- 일반목장과 대학목장 분기
- 일반목장 대상자 정보 저장
- 대학목장 대상자 안내 화면
- 제출 완료 메시지
- 개인정보 수집 동의
- 모바일 반응형 UI

### 4단계: 운영 테스트

테스트 항목:

- iPhone과 Android에서 QR 접속이 잘 되는지
- 한국어와 영어 입력이 잘 되는지
- 연락처 중복 입력을 확인할 수 있는지
- 대학목장 대상자가 일반 DB에 저장되지 않는지
- 팀원이 데이터를 확인하기 쉬운지
- 실제 주일 현장에서 3-5명 정도 테스트했을 때 작성 시간이 적절한지

### 5단계: 확장 기능

운영이 안정되면 아래 기능을 추가할 수 있다.

- 관리자 로그인
- 새가족 상태 관리
- 담당자 배정
- Notion 연동
- 자동 알림
- 주간 리포트
- 중복 등록 감지
- 대학팀 별도 등록 페이지
- 새가족 환영 메시지 자동 발송

## 10. 추천 MVP 범위

처음 버전은 너무 크게 만들지 않고, 실제 현장에서 바로 테스트 가능한 수준으로 만든다.

### MVP 포함 기능

- QR 등록 페이지
- 첫 질문으로 일반목장과 대학목장 분기
- 일반목장 대상자만 Google Sheets에 저장
- 대학목장 대상자는 안내 페이지로 이동
- 제출 완료 화면
- 개인정보 수집 및 이용 동의
- 모바일 최적화 디자인

### MVP에서 제외해도 되는 기능

- 관리자 로그인
- 복잡한 대시보드
- Notion 양방향 연동
- 자동 카카오톡 메시지
- 고급 통계

초기에는 Google Sheets를 관리 화면으로 사용하고, 운영 방식이 안정된 후 관리자 페이지와 Notion 연동을 추가하는 것이 좋다.
